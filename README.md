# Weather Data ETL & Forecast Accuracy Reporting (Bash)

A set of Bash scripts that pull live weather data, log it on a schedule via `cron`, and analyze forecast accuracy over time. Built as a hands-on project for IBM's DevOps/Software Engineering coursework, applying core Linux shell scripting concepts: process automation, data extraction with `cut`/`grep`, arrays, and conditional logic.

## Step 1: Pull and log weather data

`rx_poc.sh` hits [wttr.in](https://wttr.in/) for a given city, pulls the current observed temperature and the forecasted temperature, and extracts both with `grep`/`cut`. Each run appends a tab-delimited record (year, month, day, observed temp, forecasted temp) to `rx_poc.log`.

## Step 2: Schedule it to run automatically

Rather than running `rx_poc.sh` by hand, I scheduled it with `cron` to run once a day. That way `rx_poc.log` builds into a real time-series of observed vs. forecasted temperatures with no manual work.

## Step 3: Measure forecast accuracy

Once there were at least two days of data in the log, I wrote `fc_accuracy.sh` to check how good the forecasts actually were. It pulls yesterday's forecasted temperature and today's actual observed temperature, calculates the difference, and labels the result: excellent, good, fair, or poor depending on how close the forecast came. Each result gets appended to `historical_fc_accuracy.tsv`.

One issue I ran into: `rx_poc.log` is tab-delimited, but my first version of the script split fields on spaces, so the variables came back empty. Fixed it by splitting on `$'\t'` instead and adding a `grep -Eo` to strip out stray characters (like units) from the extracted numbers.

## Step 4: Report weekly stats

Last step was `weekly_stats.sh`, which works off a larger synthetic dataset (downloaded, not generated by my own log) so there's enough history to actually calculate a week's worth of stats. It loads the last 7 days of forecast accuracy values into a Bash array, converts any negative values to their absolute value, then loops through to find the minimum and maximum absolute forecast error for the week.

## Skills demonstrated

- Scheduling recurring jobs with `cron` / `crontab`
- Parsing and transforming delimited text data (`cut`, `grep -Eo`, tab vs. space delimiters)
- Bash arrays and loops
- Conditional branching for data classification
- Debugging a real delimiter mismatch bug between a log file and a parsing script
- Building a small but complete ETL pipeline: extract (curl/wttr.in) → transform (parse temps, calculate accuracy) → load (append to log/report files)

## Files

```
scripts/
  rx_poc.sh              # Weather ETL script (run daily via cron)

  weekly_stats.sh         # Weekly min/max error report

```

## Notes

`rx_poc.sh` depends on `wttr.in` being reachable and generates `rx_poc.log`, which the other two scripts read from (or a synthetic dataset, in the case of `weekly_stats.sh`). These aren't included since they're generated/downloaded data, not source code.
